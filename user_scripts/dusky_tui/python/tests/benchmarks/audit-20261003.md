# Shared TUI audit — 2026-10-03

Historical first-pass snapshot. The [second-pass audit](audit-20261003-second-pass.md) supersedes its compatibility policy, production source identities and current verification results. The original measured artifacts remain preserved.

Green Light for the tested shared framework. The three requested production files were audited in full, with relevant engine/schema callers inspected. Changes apply to consumers of this shared framework; they do not migrate every launcher to another interpreter.

## 1. Macro audit

- Replaced the lazy engine `dict` subclass with a proper `MutableMapping`. The original could construct duplicate engines under concurrent lookup and retain registered keys after `clear()`. Registration, membership and iteration remain lazy; unknown lookups now raise `KeyError`. Shutdown inspects only initialized engines. Construction stays on the requesting worker, and `set_app` binds once on the UI thread. A focused simultaneous UI/worker lookup verified that the factory lock is released before waiting for the UI callback.
- Deferred discovery registers newly introduced engine/target pairs before loading them, then records their state and readiness. Previously those targets could be absent from the pool and startup bookkeeping.
- Selected dependencies use Python 3.15's PEP 810 `__lazy_modules__`. Hidden Markdown help now mounts on first opening. Existing system-Python launchers still parse the same source without version branches; native import deferral requires Python 3.15. Programmatic help callers must now await `action_toggle_help()`.
- Kept the existing shared UI architecture and startup instrumentation. No backend redesign, global interpreter replacement, or speculative compatibility layer was added.

## 2. Micro audit

Fixed absent-state versus present-null handling across boot, refresh, discovery and external watching; name-keyed custom-view option groups; read-only render-cache invalidation; and removed-key visibility during external reload. Fixed the undefined editor command on left click and restored right-click terminal-editor selection with quoted `VISUAL`/`EDITOR` arguments. File-creation errors now stop that action cleanly.

Exact built-in cloning avoids expensive class-pattern matching while custom subclasses retain their type and attributes through `deepcopy`. Built-in config containers remain an acyclic-value API. Color handling avoids loading optional color data for known names, recognizes special CSS fallback names, validates six/eight-digit `0x` colors, and handles HSL overflow. A lone double-quote character is preserved during string deserialization.

The launcher respects `-B` and explicit bytecode-cache prefixes, handles a non-root invoking user with primary GID zero, preserves Wayland environment variables, and sends logging/backup notices to stderr so machine-readable exports remain clean. Empty `--set`/`--reset-key` arguments are rejected instead of starting the TUI. Redundant tab-name logic was removed.

## 3. Empirical verification

Installed environment: `/usr/local/bin/python3.15` is **3.15.0rc3**, with PGO/LTO, the GIL, no available JIT, and no frame pointers. Created the requested `$HOME/.venvs/315` with Textual **8.2.8** and Rich **15.0.0**, matching system packages. `/usr/bin/python` remains **3.14.7**; pacman packages are unchanged. Confirmed relevant runtime floors: kernel 7.3.0-rc5, systemd 262, Hyprland 0.56.2, fzf 0.74.4 and Bash 5.3.20. These are observed development versions, not proof of a future ISO's final package manifest.

The unmodified baseline ran 192 tests with two errors from stale firewall test fixtures: real host-file inspection and a mock passed to Rich as text. Fixtures were updated to the current stored-rule API and isolated from host state; firewall production code was unchanged. The final suite runs **210 tests successfully on each interpreter**: 40.792 s on 3.15 and 41.835 s on 3.14. Coverage includes mapping/concurrency, worker/UI binding, deferred targets, shutdown, multi-target CLI writes/defaults/exports, lazy help, null values, rendering and reload regressions. Syntax and Git whitespace checks passed. A temporary-file atomic backup/restore round trip and stderr isolation passed.

### Matched before/after measurements

Both variants used the same native 3.15 interpreter, dependencies and isolated INI workload. Invocation order alternated. Process measurements used 31 samples per variant after three warmup pairs; lifecycle measurements used 11 warm-cache pairs and five fresh-bytecode pairs, at 120×40 with tabs 1/2 and 0.5 s observation. Original sources were preserved before editing; final process-report SHA-256 hashes match the final production files. All 32 lifecycle records completed without recorded errors.

Fresh bytecode means separate empty `XDG_CACHE_HOME` directories for Dusky's bytecode cache, not a cold OS filesystem cache. Whole-workload CPU/RSS include navigation, observation and shutdown. Callbacks are framework milestones, not pixel presentation. First process invocations, individual samples and quartiles are retained in the raw report.

On system Python 3.14, an additional 11-sample matched process check found effectively unchanged timings: help 81.24→80.96 ms, docs 105.85→105.06 ms, core import 43.45→43.52 ms, UI import 333.20→334.68 ms. These sub-1% differences do not justify a performance claim. Use the 3.15 venv for the reported native lazy-import gains.

Isolated cloning microbenchmarks used nine alternating batches of 200,000 calls: integers 127.38→85.81 ns, strings 210.99→87.98 ns, lists 608.17→321.57 ns and nested values 1064.58→615.39 ns. These are utility costs, not whole-TUI speedups. Inclusive UI import spans in the warm lifecycle reports fell from 167.28 to 131.56 ms; Textual itself remains a substantial startup dependency. Inclusive spans overlap and must not be summed.

### Diagnostics and limits

Exercised `-X importtime=2`, `profiling.tracing` for both CLI export and the actual TUI worker, and Tachyon sampling for the worker. The saved interactive flamegraph contains shared TUI stacks. Direct worker sampling captured 1443 sampling iterations and reported an error rate of 29.24%; use it for exploratory attribution, not precise percentages. Call tracing also changes timing and includes event-loop waits; its cumulative async totals overlap. Neither profile contributed to speed samples.

`--subprocesses` produced the parent report but no child report. A separate attach probe confirmed process-memory permission denial on this host (`ptrace_scope=1`). The README uses direct worker sampling, which succeeded without changing permissions. A PTY terminal smoke completed at the actual 80×24 viewport and recorded a driver flush with no errors. Physical Wayland-terminal presentation, optical flicker, privileged firewall operations and all hardware backends were not exhaustively exercised. First help opening deliberately pays the deferred Markdown import/mount cost.

Raw reports, test logs, source snapshots, dependency versions, the lifecycle comparison driver, call profiles and the interactive worker flamegraph are saved under `${XDG_STATE_HOME:-$HOME/.local/state}/dusky/audits/20261003-shared-core`; `manifest.json` records artifact hashes.
