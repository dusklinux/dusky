# Dusky Snap startup and efficiency review

Reviewed 2026-10-23 against commit `985aa464`. All original Snap Rust modules,
its configuration, and its Cargo/launch settings were reviewed. Dusky Center
and Tray supplied read-only startup, graphics and worker references. Changes
are confined to Snap. The existing setup script installs the native build.

## 1. Structure and logic

The main reported defect was missing initial state: `App::boot` initialized
`hover` to `None`, while the guides depended on hover messages generated by
mouse motion. Capture now includes Hyprland's current cursor position and
converts global logical coordinates into screenshot pixels using the output's
actual logical size. Canvas drawing also uses Wayland's pointer-enter position
when available. No cursor warp or continuous compositor polling is needed.

The initial startup pass requested fullscreen in the initial window settings.
The pinned-window fix below supersedes that approach: ordinary fullscreen
windows sit below pinned windows for pointer hit-testing in Hyprland.

Iced's existing global font discovery starts on one named thread while capture
runs. The same font system, system font list and configured family are retained;
Iced's initialization lock synchronizes drawing if discovery is unfinished.
Quick fullscreen copy/save does not start this GUI work. GPU environment setup
precedes all startup threads, and finite child commands restore the session's
original GPU environment through the existing helper.

Blocking jobs now use two separate workers, borrowing Center/Tray's separation
of blocking work from Iced's two event/timer workers. Submission remains deferred
until a task is polled; canceled queued jobs are skipped. Slow export or scroll
jobs cannot occupy the timer executor's threads. This bounds concurrency, not
the total completion latency of queued jobs.

## 2. Detailed implementation

| Path | Before | After |
| --- | --- | --- |
| Capture metadata | Separate monitor/client commands and client-query thread | One `hyprctl -j --batch` for monitors, clients and initial pointer; concatenated JSON parsed with Serde |
| Picker image | Three full-image copies during boot; two independent image handles and overlapping draws | One pixel copy and one handle; one draw normally; transformed/letterboxed picking reuses that handle for its frozen background |
| Rendered image handoff | Clone the newly rendered pixel vector into Iced | Move the owned vector into Iced |
| Recents | Scan and decode five thumbnails on every picker startup | Load when opening Recents; skip individually missing/broken thumbnails; button no longer displays an eagerly computed count |
| Plain export | Copy pixels, allocate an empty vector canvas, then scan it | Direct native-pixel crop when no annotations/backdrop/growth need composition |
| Raster-only annotations | Allocate and scan an unused vector canvas | Return after raster processing if no vector layers remain |
| Finite commands | Two reader threads, optional writer thread, 3 ms exit polling | Nonblocking stdin/stdout/stderr and a pollable process descriptor under one deadline |
| Descendant pipe lifetime | Reap the leader, then join readers without a deadline | Keep leader unreaped until pipes close; timeout/I/O failure kills its process group and reaps the leader |

The subprocess change fixes an actual indefinite-wait path: a child can exit
while its descendant retains an inherited stdout/stderr descriptor. Process
exit alone does not mean those pipes have closed. Polling the process descriptor
and pipes together preserves the timeout. This uses the documented Linux
[pidfd lifecycle](https://man7.org/linux/man-pages/man2/pidfd_open.2.html) and
[poll semantics](https://man7.org/linux/man-pages/man2/poll.2.html). Closed output
pipes also do not incorrectly finish a child that is still running. Input and
both output streams make progress together, including data larger than pipe
capacity; interrupted waits retain the original deadline.

Installed `hyprctl --help` and its man page were checked, and batched JSON output
was exercised against the running compositor. The upstream
[hyprctl documentation](https://wiki.hypr.land/Configuring/Using-hyprctl/) also
documents batching. Iced window settings, cursor, renderer and font APIs were
checked against the exact locked crate sources. No dependencies or lockfile
versions changed, and no installation-time network access was introduced.

The existing conservative GPU discovery and explicit GPU/backend preferences
are retained. Snap already had Center's GPU filtering helper. Adding Center's
custom renderer wrapper would require adapting its canvas and image rendering
interfaces as well; that extra implementation was not needed for these fixes.
The application retains its normal on-demand lifecycle and software fallback.

## Follow-up audit and stress pass

The second pass used clean commit `b2a20ea6` as its baseline. Its results below
supersede the earlier test count. No dependencies or package versions changed.

Additional changes:

- Iced's existing `Bytes::from_owner` API now shares the immutable screenshot
  through its existing `Arc`, removing the remaining picker source copy. A
  pointer-identity/lifetime test verifies the handle uses the same allocation
  and keeps it alive after the document is dropped. This avoids a 31.6 MiB pixel
  allocation for a 3840×2160 image; application-wide RSS was not measured.
- Raster source copying uses contiguous row copies. Alpha values and original
  RGB bytes remain untouched; actual blending still uses the existing blend
  implementation. Crop clipping, fractional coordinates, negative grown origins
  and empty source intersections have explicit regression coverage.
- Cut/insert replay borrows the original source until a transformed image is
  needed and copies whole row ranges, removing the initial full-source clone
  and temporary top/bottom images.

## Pinned-window follow-up

Two independent defects caused pinned windows to be missed. Capture filtered
out pins assigned to a different workspace, and focus history could place the
underlying tiled window ahead of the pin. Selection now includes pins across
workspaces and ranks pinned, floating and tiled windows in that order, retaining
focus order within each group. Hidden and off-output rectangles stay excluded.
Two regression tests cover these cases, special workspaces, negative monitor
origins, scaling and clipping. The complete suite now passes **38 tests**, with
zero failures/ignored; formatting and frozen Clippy with warnings denied pass.

A live Wayland trace also reproduced pointer-leave events when hovering the
pinned player: Hyprland directed input above the ordinary fullscreen picker.
The picker now opens as a borderless, monitor-sized pinned float using its own
application class. It unpins before resizing into the editor or scroll controls.
Static monitor/size/position rules use the captured output, and one asynchronous
post-map move corrects Hyprland's `new_float_force_onscreen` positioning override.
That setting empirically shifted the initial surface by two pixels here. The
fix changes only Snap's own window and requires no global compositor setting,
continuous polling, resident process or new dependency.

The verified native build is installed. Live checks passed with the existing
pinned player on workspace 1 while capturing workspace 2: Wayland motion stayed
in Snap without pointer-leave events over the player; a real virtual-pointer
click selected its exact **237×134** rectangle. Default rendering and explicit
Tiny Skia both passed the editor transition, unpin and persisted-crop checks.
Quick-save wrote a valid 237×134 PNG with the same crop. An ordinary tiled window
still selected its exact 1264×704 bounds, and duplicate invocation dismissed the
pinned picker cleanly. Test documents/output used isolated temporary runtime
directories, and the original pointer position was restored.

The pinned-float approach covers ordinary application windows, including
fullscreen applications. Layer-shell panels/overlays retain their compositor
layer priority; this is not an exclusive layer-shell screenshot surface.
Physical multiple-output and fractional-scale UI sessions remain untested;
coordinate conversion has automated fixture coverage. No new startup speedup
is claimed for this correctness change; it adds one post-map IPC command.

## Dusky Tray focus-grab follow-up

Tray is a regular pinned Wayland window, not a layer-shell panel. Its shared
click-away helper holds a Hyprland focus grab restricting input to Tray's own
surface. A live baseline reproduced the report: the picker mapped above Tray,
but received no hover motion outside it, and Tray kept its grab.

After capture, the interactive picker/editor now briefly commits a focus grab
for its own Winit surface and immediately destroys it. Hyprland clears the old
grab; Tray's existing cleared callback dismisses the live popup. Its image and
window rectangle were already captured, so the frozen Tray remains visible and
selectable in Snap. The picker then uses ordinary pointer input. Preview/pin
windows do not claim focus this way, and quick fullscreen output still avoids
all GUI initialization. Tray and its shared C helper require no changes.

The handoff runs through Iced's documented window callback. A guest Wayland
backend borrows the live display only for that callback; no borrowed handle
escapes it, no surface event handler is replaced, and no extra reader thread,
polling, compositor configuration or named-process dismissal is added. Two
one-time Wayland round trips perform registry discovery and request completion.
The existing focus-grab v1 XML is vendored with its copyright intact.
`wayland-scanner` was already locked/cached and is now a direct compile-time
dependency; the required system-backend feature is explicit. No crate versions
or additional packages were introduced, and the build remains frozen/offline.

Default-renderer and Tiny Skia live checks both received hover motion over
different parts of the frozen desktop, selected Tray with a real pointer click,
persisted its exact **320×532** crop and transitioned to an unpinned editor.
The full **38-test** suite, formatting and Clippy with warnings denied pass.
No startup improvement is claimed: this is a one-time input handoff fixing an
observed defect, with no ongoing work after the handoff.

The verified native release is installed. Its live default-renderer/software
picker and fullscreen-editor checks pass. The second pass also verified:

- Five consecutive native cycles: Tray starts with an active grab, Snap receives
  hover motion, a real click selects the exact Tray rectangle, the editor unpins,
  and both applications exit cleanly.
- With the pointer stationary outside the fullscreen editor's bounds, Snap
  retains keyboard focus after Tray dismisses; no mouse motion is needed.
- A regular pinned screenshot preview stays alive and selects its exact
  324×227 client rectangle; the handoff does not close ordinary pinned windows.
- Opening a passive pinned preview leaves the existing Tray and its active
  focus grab intact. Only interactive Snap windows perform the handoff.
- Tracing places the handoff after the picker's first surface-buffer attachment.
  The borrowed-display API and proxy construction match the locked Wayland
  library's documented FFI interface. The grab and manager are destroyed within
  the callback, and no protocol state or raw handle is retained in application
  state. Earlier physical multiple-output/layer-shell limitations still apply.

## Quick-copy flash, editor readiness and individual windows

The quick-selection handler unconditionally changed to `Phase::Edit` before
checking whether annotation was requested. Its clipboard worker then ran while
the editor layout displayed the original desktop texture. Annotation likewise
resized the window before its asynchronous cropped render completed. These
were real state/asset ordering defects, not a requested preview.

Quick output now exports an owned selected document while retaining the original
picker state and texture. It never switches to the editor. This also preserves
the original picker for retry if clipboard/save fails. The existing editor and
quick paths share the same export helper without duplicated persistence logic.

Annotation uses an explicit transparent preparation state. A worker first
produces the selected document and its correctly cropped pixels; the editor
appears only after its final logical window size is confirmed. The final size
is also queried once: an experimentally reproduced same-size transition need
not emit a resize event. No timer, arbitrary sleep, polling loop or extra process
is needed. Escape can cancel preparation. Capture/render errors return to the
intact picker; resize errors show the correctly cropped editor with the error.

The previous window-click path cropped the already composited monitor image,
which necessarily included pinned windows in front. Individual-window capture
is available on this compositor through the existing locked libwayshot API.
Targets now retain Hyprland's stable ID, matched exactly against the standard
foreign-toplevel identifier. A window click captures that window's **current
surface**, including portions obscured by other windows. It does not infer
hidden pixels, move/unpin the other windows or match ambiguous titles/classes.
There are no new dependencies or external capture commands in the application.

Dragging and scroll selection continue to use the frozen monitor pixels, with
all visible overlap included. A closed popup, absent identifier or unavailable
window-capture capability uses the frozen crop; this preserves the captured
Tray after its live click-away window dismisses. Window frame capture errors
leave the picker available for retry. Individual window capture happens only
after a click, adding no per-window image capture to startup.

Live comparisons caught premultiplied RGB in the returned transparent window
buffers. Window capture now converts this to the straight alpha required by
the document/PNG pipeline, following the installed Wayland buffer specification.
Opaque pixels remain unchanged. Tests cover opaque, partial and zero alpha.

Verification includes **41 passing tests**, zero failures/ignored, frozen Clippy
with warnings denied and formatting checks. Regression tests exercise quick
copy/save without an editor phase, failed export retries, configure arriving
before pixels, old picker-size events and final editor readiness. Existing
initial-frame, pinned-window, raster, export and stress regressions still pass.

An overlapping-window fixture uses a red 700×500 client and a blue pinned client
in front. Clipboard pixels match the isolated red window; a 630×380 dragged
region matches the composited desktop crop exactly, including the blue overlap.
Annotation opens with the isolated window document. Real screenshot previews
also matched all opaque pixels; a few partially transparent edge channels
differed from grim's float-based unpremultiplication by at most one level.
The original clipboard payload and pointer position were restored, and fixture
windows/rules were removed or disabled after testing. Multi-output hardware and
fractional-scale UI limitations remain as documented above.

The final native build is installed and its source/CPU fingerprints are verified.
The complete clipboard/editor/drag pixel checks pass on that installed binary
with both automatic GPU selection and explicit Tiny Skia. The same-size editor
transition and closed-Tray snapshot selection also pass. Quick-copy's live
Wayland trace retains picker dimensions until exit; it does not configure an
editor-sized window. No general startup speedup or calibrated numeric quality
score is claimed for these correctness changes.

## Full-monitor annotation blur and sharp pinned previews

The user selected blur across the entire monitor behind annotation mode.
The previous annotation window was capped at 1100 logical pixels wide and
content-dependent height. Hyprland could blur only that window rectangle.
Annotation and its preparation state now cover the captured monitor's full
logical size, positioned at its global origin rather than centered in the
reserved work area. Controls/image remain centered in a compact content group.
Preview and scroll-control sizing remain bounded as before.

Snap's default window rule now disables compositor blur. A dynamic rule allows
blur only for a ready annotation window that is not pinned, identified by the
application's annotation title and class. This respects the user's global blur
setting and disables blur again when the editor itself is pinned. Pinned image
previews and the picker have no blur. Annotation transitions also disable window
animation, avoiding an expanding partial blur rectangle. No global Hyprland
setting, image pixels or dependencies changed. Initial file/fullscreen editors
receive one post-map move to the monitor origin; picker transitions reuse the
existing positioning and resize IPC. There is no blur-setting query or polling.

All **41 tests** pass, including updated monitor-size readiness expectations,
and frozen Clippy/formatting pass. A live GPU checkerboard fixture confirms the
editor at **[0,0], 1280×720**, with all 3600 pixels in each of four 60×60 corner
patches changed by blur. Pinning the editor restores exact sharp background
pixels; unpinning restores blur. The pinned preview's transparent padding also
matches the sharp background exactly. The fixture changes only owned windows
and temporary rules; the user's enabled global blur setting is retained.

The explicit Tiny Skia fallback cannot provide this translucent backdrop:
locked softbuffer 0.4.8 uses opaque XRGB8888 Wayland buffers. Its editor remains
usable with an opaque background. Replacing that backend solely for compositor
blur is outside this focused change; full-monitor glass blur requires the GPU
renderer. Physical multi-output and fractional-scale UI caveats still apply.

The final verified native build is installed. Its checkerboard/pin/unpin checks,
clipboard/editor/region pixel comparisons and closed-Tray workflow all pass.
The user's global blur remains enabled. No blur-performance benchmark is
claimed: extending the requested blur area naturally increases its pixel work.

## Special-workspace annotation placement

The live baseline reproduced an annotation jump from a named special workspace
to its underlying normal workspace. Hyprland's pin dispatcher explicitly assigns
an unpinned window to the monitor's normal active workspace. Snap's pinned picker
therefore lost the special-workspace context when becoming an editor.

The captured monitor already records both workspace addresses. A shared borrowed
`Monitor::workspace()` selector now prefers the visible special workspace and
otherwise uses the normal workspace. Resizing/unpinning restores that invocation
workspace before applying the final geometry. The move follows the editor so
keyboard focus is retained: a silent move was experimentally shown to leave
focus behind. Initial file/fullscreen editors also receive explicit workspace
placement and focus. Picker startup focus preserves the pointer's original
position, avoiding a new cursor/selection jump from Hyprland's focus dispatch.

This uses the existing geometry/startup IPC batches and captured metadata, with
no new query process, polling or workspace-name-specific rule. Workspace strings
are JSON-quoted for Lua, and the chosen scope is the capture's invocation scope.

All **42 tests** pass, including a regression for normal/named normal workspaces,
Magic and other named special workspaces. Formatting and frozen Clippy with
warnings denied pass. Live region, window-click, direct fullscreen annotation
and file-editor paths retain the special workspace, visibility and keyboard
focus. The underlying normal workspace remains unchanged; the picker does not
close the special workspace or move the initial cursor. Ordinary-workspace
annotation also passes. Fixtures restore the previous special-workspace
visibility and cursor and use isolated temporary screenshot history.
