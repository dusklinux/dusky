# Dusky Snap startup and efficiency review

Reviewed 2026-10-23 against commit `985aa464`. All original Snap Rust modules,
its configuration, and its Cargo/launch settings were reviewed. Dusky Center
and Tray supplied read-only startup, graphics and worker references. Changes
are confined to Snap. The existing setup script installs the native build.

## 1. Structure and logic

The main reported defect was missing initial state: `App::boot` initialized
`hover` to `None`, while the guides depended on hover messages generated by
mouse motion. Capture now includes Hyprland's current cursor position and
converts global logical coordinates into screenshot pixels using the output's
actual logical size. Canvas drawing also uses Wayland's pointer-enter position
when available. No cursor warp or continuous compositor polling is needed.

The initial startup pass requested fullscreen in the initial window settings.
The pinned-window fix below supersedes that approach: ordinary fullscreen
windows sit below pinned windows for pointer hit-testing in Hyprland.

Iced's existing global font discovery starts on one named thread while capture
runs. The same font system, system font list and configured family are retained;
Iced's initialization lock synchronizes drawing if discovery is unfinished.
Quick fullscreen copy/save does not start this GUI work. GPU environment setup
precedes all startup threads, and finite child commands restore the session's
original GPU environment through the existing helper.

Blocking jobs now use two separate workers, borrowing Center/Tray's separation
of blocking work from Iced's two event/timer workers. Submission remains deferred
until a task is polled; canceled queued jobs are skipped. Slow export or scroll
jobs cannot occupy the timer executor's threads. This bounds concurrency, not
the total completion latency of queued jobs.

## 2. Detailed implementation

| Path | Before | After |
| --- | --- | --- |
| Capture metadata | Separate monitor/client commands and client-query thread | One `hyprctl -j --batch` for monitors, clients and initial pointer; concatenated JSON parsed with Serde |
| Picker image | Three full-image copies during boot; two independent image handles and overlapping draws | One pixel copy and one handle; one draw normally; transformed/letterboxed picking reuses that handle for its frozen background |
| Rendered image handoff | Clone the newly rendered pixel vector into Iced | Move the owned vector into Iced |
| Recents | Scan and decode five thumbnails on every picker startup | Load when opening Recents; skip individually missing/broken thumbnails; button no longer displays an eagerly computed count |
| Plain export | Copy pixels, allocate an empty vector canvas, then scan it | Direct native-pixel crop when no annotations/backdrop/growth need composition |
| Raster-only annotations | Allocate and scan an unused vector canvas | Return after raster processing if no vector layers remain |
| Finite commands | Two reader threads, optional writer thread, 3 ms exit polling | Nonblocking stdin/stdout/stderr and a pollable process descriptor under one deadline |
| Descendant pipe lifetime | Reap the leader, then join readers without a deadline | Keep leader unreaped until pipes close; timeout/I/O failure kills its process group and reaps the leader |

The subprocess change fixes an actual indefinite-wait path: a child can exit
while its descendant retains an inherited stdout/stderr descriptor. Process
exit alone does not mean those pipes have closed. Polling the process descriptor
and pipes together preserves the timeout. This uses the documented Linux
[pidfd lifecycle](https://man7.org/linux/man-pages/man2/pidfd_open.2.html) and
[poll semantics](https://man7.org/linux/man-pages/man2/poll.2.html). Closed output
pipes also do not incorrectly finish a child that is still running. Input and
both output streams make progress together, including data larger than pipe
capacity; interrupted waits retain the original deadline.

Installed `hyprctl --help` and its man page were checked, and batched JSON output
was exercised against the running compositor. The upstream
[hyprctl documentation](https://wiki.hypr.land/Configuring/Using-hyprctl/) also
documents batching. Iced window settings, cursor, renderer and font APIs were
checked against the exact locked crate sources. No dependencies or lockfile
versions changed, and no installation-time network access was introduced.

The existing conservative GPU discovery and explicit GPU/backend preferences
are retained. Snap already had Center's GPU filtering helper. Adding Center's
custom renderer wrapper would require adapting its canvas and image rendering
interfaces as well; that extra implementation was not needed for these fixes.
The application retains its normal on-demand lifecycle and software fallback.

## 3. Verification and measurements

- Baseline: 23 tests passed. Final: all 31 tests passed, including the normally
  ignored rendered-frame test; zero failures or ignored tests in that run.
- The rendered-frame regression checks initial crosshairs, window dimming and
  untouched selected pixels without sending any pointer-motion events, at
  1.0, 1.5 and 2.0 scale. It also checks the frozen background under zoom/pan.
- Tests cover batched JSON errors, negative monitor origins, scaled pointer
  conversion, two blocked workers with an independent timer, large simultaneous
  pipe traffic, empty input, early stdin closure, command failure, inherited
  input/output pipes after leader exit, and closed pipes while the child remains
  alive.
- Existing native/fractional crop, export, annotation, blur, undo/redo, band
  editing, scroll stitching and GPU discovery regressions pass.
- `cargo fmt --check` and frozen/offline Clippy with `--all-targets -D warnings`
  pass. Optimized release compilation and native installation pass.
- Live default-GPU, explicit EGL and Tiny Skia picker smoke launches pass.
  Ordinary opening reports fullscreen state, and duplicate invocation dismisses
  the picker with successful persistence/exit.
- Live fullscreen copy/save produces byte-identical PNG data in the clipboard
  and output file. File, clipboard, pin, fullscreen-editor and region smoke
  paths pass. The previous clipboard payload was restored after the check.

Six alternating before/after native release pairs measured process launch to
the first non-null Wayland surface buffer attachment using `WAYLAND_DEBUG=1`.
Both binaries used the existing CPU-native release recipe and the same session.

## Follow-up audit and stress pass

The second pass used clean commit `b2a20ea6` as its baseline. Its results below
supersede the earlier test count. No dependencies or package versions changed.

Additional changes:

- Iced's existing `Bytes::from_owner` API now shares the immutable screenshot
  through its existing `Arc`, removing the remaining picker source copy. A
  pointer-identity/lifetime test verifies the handle uses the same allocation
  and keeps it alive after the document is dropped. This avoids a 31.6 MiB pixel
  allocation for a 3840×2160 image; application-wide RSS was not measured.
- Raster source copying uses contiguous row copies. Alpha values and original
  RGB bytes remain untouched; actual blending still uses the existing blend
  implementation. Crop clipping, fractional coordinates, negative grown origins
  and empty source intersections have explicit regression coverage.
- Cut/insert replay borrows the original source until a transformed image is
  needed and copies whole row ranges, removing the initial full-source clone
  and temporary top/bottom images.
- Scroll stitching compares existing tail bytes without allocating a viewport
  copy, copies output spans directly, and avoids trimming/re-copying the entire
  growing image when there is no sticky footer. Existing overlap scoring,
  alignment thresholds, footer behavior and size limits remain intact.
- Final output makes its thumbnail from the image already rendered for PNG
  export. The full rendered image is dropped before persistence; persistence
  receives only the small thumbnail rather than rendering the document again.
- A demonstrated autosave ordering defect is fixed under the existing global
  document lock: revision 2 followed by a late revision 1 previously restored
  revision 1. Existing working revisions now reject equal/older snapshots.
  Concurrent saves and completed-document suppression have regression coverage.
- The redundant second persistence lock was removed; `documents.lock` continues
  to serialize working/completed writes and history pruning. Private storage
  helpers accept a root path so concurrency fixtures use isolated directories.
- GPU comments were corrected: Snap uses Iced's normal backend discovery and
  software fallback, not Center's custom Vulkan-first compositor wrapper.

Optimized CPU fixture benchmarks used the same compiler options/dependencies
before and after, with native CPU optimization. These are isolated render/
stitch timings, not end-to-end capture or UI latency. Render rows use the median

## Pinned-window follow-up

Two independent defects caused pinned windows to be missed. Capture filtered
out pins assigned to a different workspace, and focus history could place the
underlying tiled window ahead of the pin. Selection now includes pins across
workspaces and ranks pinned, floating and tiled windows in that order, retaining
focus order within each group. Hidden and off-output rectangles stay excluded.
Two regression tests cover these cases, special workspaces, negative monitor
origins, scaling and clipping. The complete suite now passes **38 tests**, with
zero failures/ignored; formatting and frozen Clippy with warnings denied pass.

A live Wayland trace also reproduced pointer-leave events when hovering the
pinned player: Hyprland directed input above the ordinary fullscreen picker.
The picker now opens as a borderless, monitor-sized pinned float using its own
application class. It unpins before resizing into the editor or scroll controls.
Static monitor/size/position rules use the captured output, and one asynchronous
post-map move corrects Hyprland's `new_float_force_onscreen` positioning override.
That setting empirically shifted the initial surface by two pixels here. The
fix changes only Snap's own window and requires no global compositor setting,
continuous polling, resident process or new dependency.

The verified native build is installed. Live checks passed with the existing
pinned player on workspace 1 while capturing workspace 2: Wayland motion stayed
in Snap without pointer-leave events over the player; a real virtual-pointer
click selected its exact **237×134** rectangle. Default rendering and explicit
Tiny Skia both passed the editor transition, unpin and persisted-crop checks.
Quick-save wrote a valid 237×134 PNG with the same crop. An ordinary tiled window
still selected its exact 1264×704 bounds, and duplicate invocation dismissed the
pinned picker cleanly. Test documents/output used isolated temporary runtime
directories, and the original pointer position was restored.

The pinned-float approach covers ordinary application windows, including
fullscreen applications. Layer-shell panels/overlays retain their compositor
layer priority; this is not an exclusive layer-shell screenshot surface.
Physical multiple-output and fractional-scale UI sessions remain untested;
coordinate conversion has automated fixture coverage. No new startup speedup
is claimed for this correctness change; it adds one post-map IPC command.
