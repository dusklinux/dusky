# Adaptive Glass Power Hub v2.3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the legacy Power action grid with a compact, riced Power Hub that shows battery context, native power profiles, dynamic Caffeine state, and safe session actions.

**Architecture:** `PowerControl.tsx` owns the visual composition and binds directly to `AstalBattery` and `AstalPowerProfiles`. `lib/powerState.ts` provides the dynamic Hypridle/Caffeine state by polling the real process and delegates toggling to the existing Dusky script. Restart and shutdown use a local confirmation state so destructive actions require a second click without spawning another popup.

**Tech Stack:** AGS v3, Gnim TSX, GTK4, AstalBattery, AstalPowerProfiles, Hyprland/Dusky shell helpers, pytest contract tests.

## Global Constraints

- Preserve the existing Dark mode and Frosted Mist Light mode language.
- Beauty-first ricing must not reduce readability, click targets, or state clarity.
- Keep the Power popup compact (~300 px), with no large square action grid.
- Caffeine ON means Hypridle is not running; Caffeine OFF means Hypridle is running.
- Reuse `~/user_scripts/waybar/toggle_hypridle.sh` for the actual Caffeine toggle.
- Lock and Sleep execute immediately; Restart and Shut down require inline confirmation.
- Power profile buttons only expose profiles actually reported by AstalPowerProfiles.
- Do not modify Workspace, Calendar, Network, Audio, Display behavior, popup semantics, or Waybar.
